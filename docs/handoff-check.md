# 新機交接驗收

請由第一次使用本專案的人，在有相容 NVIDIA GPU 的 Windows 環境執行[安裝手冊](setup.md)。先記 Git commit、Windows／Docker／GPU 版本，以及是否已有 uv、Hugging Face 或 Docker 快取。沒有乾淨新機時，可以重做資料與索引流程，並如實記錄共用了哪些執行環境。

| 檢查 | 通過時看得到什麼 | 記錄什麼 |
|---|---|---|
| 依手冊安裝並跑離線示範 | 六個情境都符合預期 | 安裝命令、第一個錯誤、是否需要作者補充操作 |
| 下載教材與建立索引 | 五份 PDF 全部通過雜湊檢查，CPU 混合檢索回傳頁碼與索引 ID | `git rev-parse HEAD`、索引 ID、嵌入模型 revision |
| 以新快取取得生成模型 | vLLM 的 `/v1/models` 列出 `qwen3-vl-8b-fp8` | 模型 revision、下載是否完成、是否重用 volume |
| 啟動 RAG 與 AnythingLLM | UI 設為 `rag`，用「請問差分隱私跟同態加密的差異」得到有教材引用的回答 | 工作區是否需額外設定、回答與引用頁碼 |
| 點開引用的 PDF | 瀏覽器開到引用所列的頁面，人工看該頁是否支持至少一個回答主張 | 點到的頁碼、支持該句的段落、是否有無法開啟的連結 |

每一步記「通過／失敗／未執行」，保留第一個錯誤與修復步驟。若執行者需要作者提示，記下提示內容以及手冊應補的地方，修改後請執行者重試該段。遇到錯誤先保存紀錄，避免為了重試刪除既有 volume 或改動教材雜湊。分享紀錄前移除密碼、API key、私有文件與路徑。

## 自有 PDF 的回答驗收

依[自用資料指南](custom-data.md)建立獨立知識庫，先關閉外搜。測試前記下題目、應答或應拒答、預期答案要點與支持的 PDF 頁。至少涵蓋原詞查詢、改寫、兩處證據合併、同領域但文件缺答案，以及完全離題。若文件有兩版互相衝突，加一題測是否引用正確的版本；記下本題允許使用哪些來源。

評閱時先看回答和被引用片段，逐句標「直接支持／部分支持／不支持／不確定／無引用」。選項行可獨立核對。把系統警告留到第二輪對照，記下誤報與漏報；另計有答案題中被拒答的題數，以及無答案題中被硬答的題數，各自保留分母。只看輸出頁碼的檢查無法判斷片段是否支持內容。用完的開發錯例可保留作回歸，下次要比較品質時請另用事先凍結的新題。既有結果見[回答評估](evaluation.md)。

## 同一台 Windows 電腦的隔離實測（2026-11-19）

| 驗證 | 環境與結果 |
|---|---|
| CPU 安裝與自有資料 | 從 `eb01d19` 建立獨立 clone，共用已安裝的 CPython 3.14.7 與 uv，使用空白套件快取及新 `.venv`。`uv sync --locked` 成功，README 的 `uv run --no-sync python -m ipas_hub.demo` 六個情境皆符合預期。匯入合成 Northstar PDF 後，BM25 對「Aurora log retention」首筆回傳 PDF 第 2 頁，片段寫明保存 37 天。 |
| 瀏覽器問答與跳頁 | 使用該 clone 的獨立索引、臨時 RAG 端點和全新 Chrome 設定檔。用本機測試聊天頁接既有 vLLM `qwen3-vl-8b-fp8`，問 Aurora 日誌保存期限，模型答 37 天。點引用後，Chrome PDF 檢視器實際顯示第 2／3 頁與支持文字，HTTP 回傳也與原 PDF 逐位元一致。字詞核對對正確改寫中的 `period` 仍有警告。 |

這輪實測涵蓋 CPU 依賴安裝與瀏覽器端到端引用。瀏覽器使用臨時測試聊天頁，重用既有生成服務。

合併後補驗 AnythingLLM：固定映像以空白資料目錄與獨立 Chrome 設定檔啟動，沿用手冊的 Generic OpenAI 環境變數及既有 RAG 端點。首頁直接可用。從側欄新建工作區，確認頁面使用 `rag`，提問差分隱私與同態加密的差異後收到教材及維基引用。點第一個教材連結，Chrome 顯示原 PDF 第 172／182 頁。截圖留本機，包含教材內容。臨時服務用完停止。

固定 Qwen 生成模型 revision 亦以空白快取做 Hugging Face `--dry-run` 預檢，確認 13 個檔案、約 10.6 GB。預檢使用既有 vLLM 映像的 Hugging Face CLI。權重實際下載、載入及陌生使用者獨立操作仍待完整驗收。
