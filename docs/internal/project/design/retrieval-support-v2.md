# 檢索支持範圍評估 v2 契約

使用者於本輪明確同意[診斷提案](../validation/2026-11-16-retrieval-miss-analysis.md)的獨立 v2。授權涵蓋建立標註與離線評估，不代表 AI 的每筆內容判斷已經人工確認，也不包含排序修改、LLM 選型或提交。

## 固定範圍與分類（標註前寫定）

沿用凍結的 3、4、18、23、28、32、40、49 題與主機索引，三方法各前 5 個片段。標註單位為「題號＋index_id＋片段 ID」，同片段跨方法使用同一標註；不依排名、方法或原命中與否改標。

每題先列需辨認概念、核心判準、完整解析仍需的依據。每片段記支持內容、不能支持內容、理由及來源性質，分類如下：

- `core`：片段本身明確表達該題核心判準的辨別關係，可作選擇核心概念的依據；不代表整段解析均受支持。
- `partial`：支持一部分關係、替代選項的比較，或有直接相關背景／術語，但不足達到該題核心判準。
- `none`：沒有支持該題判斷的論述；只共現泛用場景或題目選項不能當成支持。這不是宣稱該頁全部無用或內容錯誤。
- 未讀或有爭議的片段記 `unjudged`，不可自動歸為 `none`；本批要求所選範圍全部明確標註。新排序取回未標註片段時亦應報 unjudged，不繼承同頁分類。

| 題號 | 核心判準（AI 操作定義，待內容審查） | 整段解析另外需要的支持 |
|---|---|---|
| 3 | 學習／最佳化方法利用即時狀況調整路徑決策 | 建檔、文字處理及報告產出與路徑調度的區別 |
| 4 | 移除敏感欄位仍可能有代理特徵偏誤，需辨識並修正 | 措施優先性及全部替代方案的比較 |
| 18 | 差分隱私與加入雜訊保護資訊的明確關係 | 單筆加入／刪除保證及其他隱私技術比較 |
| 23 | LSTM 與時間序列／前後狀態關係的明確連結 | 各個影像、分組情境的適配與排除理由 |
| 28 | 有標記的監督式學習與連續數值迴歸的關聯 | 線性迴歸、MAE 與其他方法及指標的全部搭配理由 |
| 32 | 注意力或自注意力與遠距依賴的明確關聯 | 非逐步傳遞及其餘架構細部比較 |
| 40 | 模式崩潰與生成多樣性退化現象的明確定義關係 | 與其餘訓練失敗現象的完整區別 |
| 49 | 鑑別式的判斷／分類與生成式的新內容產出的對照 | 場景映射、風險分數判定與深度學習不等於生成式的理由 |

只把術語出現當 partial；完整頁可釐清上下文，但不得將鄰塊文字偷偷算進被檢索片段。未附解答的教材選項列為 `exercise_question`、不當成正確敘述；教材解答列 `exercise_answer`，仍逐段判讀，不能只看答案字母。正文列 `exposition`。本輪不改語料範圍。

每片段另列 `full_explanation_support`（sufficient／insufficient／uncertain）及缺口；每方法的前五集合也獨立記一次，不能因沒有單塊充分就推定集合不足，也不能因有 core 就推定集合充分。充分需涵蓋目前參考解析的核心及全部選項理由；必要的情境推論與未查證知識必須揭露。

## 完整性、版本與評估方法

標註範圍為每題三方法前五聯集、原 expected 頁的全部片段，及前輪明列的補查候選。全 8 題一律如此，不只增加未命中題依據。這是有限池的後驗標註，沒有聲稱涵蓋全語料或盲審；未列入的片段保持未評。

資料另存 `data/evaluation/rag-retrieval-support-v2.json`，包含父案例、診斷、頁面與解析 SHA-256、index_id、標註者 AI、日期、規則版本、授權來源、人工狀態與每題修訂理由。原 query 與 expected 保留在 parent 對照欄，不修改或替換 v1。新檔不是舊 CLI evaluate 的 cases 格式，不交給舊評估器誤算。

以本機獨立腳本對凍結結果產生 24 列，每列顯示原 v1 命中、前五 core／partial／none／unjudged 數量、core 位置與前五集合的完整解析支持。計數只描述這批 AI 標註，不能與 v1 的頁碼命中率相減宣稱進步；沒有新的品質通過門檻。

驗證：所有題號、片段 ID、原文雜湊、來源頁及排序均匹配；所有前五與規定參考片段都有標註，同片段跨方法一致；24 列各合計 5；原 v1 三方法各 5／8；未知片段不能默認為不支持；全部舊輸入雜湊保全。檢查實際資料與腳本計算，不重跑模型／Docker，也不為文件新增應用單元測試。

人工只需確認資料中標出的關鍵判讀；AI 已整理原文對照與理由，不要求使用者另找來源。新的內容審查意見以另版檔案或獨立審查紀錄保存，不能覆寫原 v1 或假裝先前已確認。
