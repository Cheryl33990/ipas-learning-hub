# 只用題幹查詢的單因素比較

結論：不採用一律移除選項。全八題中三方法的原頁碼命中及 AI 核心支持題數均下降，未有新增核心命中。

## 固定因素與執行

HEAD 5cf7d96 加既有未提交成果；沿用主機 index_id 19a8fa4bc06d4f90c6fa53b77dac71a063afcae279ed91522f291e1d603d3108、266 塊、400 字／300 步長，以及原 v2 支持判準。BAAI/bge-m3 使用本機快取 revision 5617a9f61b028005a4858fdac845db406aefb181、CPU、離線模式。三方法排序及混合的兩路前 20 排名融合均維持原程式。

唯一變因：在第一個選項標記前截斷原查詢，僅去末尾空白，不摘要、不加入答案、不改寫問句。八題的四個選項標記各出現一次，原文及截取結果在 data/evaluation/stem-query/queries.json。

先對每題原查詢重跑，全部 24 組前 20 個片段 ID 與凍結診斷相同，再執行題幹查詢。每查詢單筆編碼，三方法共用該查詢向量；正式 search 取得前 20，評估仍 k=5。腳本 data/evaluation/experiment_stem_query.py；結果與輸入 SHA-256 在 data/evaluation/stem-query/results.json。索引、向量、原案例、診斷、v2、檢索程式及 uv.lock 雜湊前後一致。

## 原因與下一步

已確認的操作效果是刪除選項後改變排名；不能據此宣稱每個選項都能幫助檢索。AI 推論是：部分選項帶有關鍵技術名稱或需要判斷的應用情境，全部移除也會失去有效線索。例如第 23 題題幹只有 39 字，具體候選情境在選項；第 49 題的模型類型術語在選項，移除後偏向一般應用或模型維護片段。題幹查詢也取回教材練習題與參考書目，延續既有語料範圍限制。

目前保留原完整查詢是有比較依據的選擇。建議先收斂這兩輪未奏效的預處理，不再用同八題反覆挑門檻或查詢寫法。下一個最小工作是整理可用範圍與證據缺口清單，區分「教材有依據但未排進前五」與「現有片段不足」，再決定是否用額外、獨立標註案例驗證泛化。MAE 外部依據另列，不把教材缺口交由排序改善背書。

本輪實跑本機編碼與檢索，未執行 pytest、Docker、CI 或 LLM；編碼耗時僅作執行紀錄，未作暖機／多次端到端延遲比較，不宣稱速度改善。未修改正式查詢、索引、原案例或歷史結果，未提交發布。
