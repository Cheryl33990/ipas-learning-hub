# 專案簡述

iPAS AI 應用規劃師備考輔助：讓每一道題目都能找到教材出處，之後再提供選項解析。本檔是範圍與成功條件的單一來源。

## 原始描述
- 我想改善的困擾／期待（使用者原話，2026-11-16）：「我看到題目不知道要怎麼選，拿關鍵字去 CTRL F 查教材，還需要自己判定是哪邊錯。所以我會希望有可以知道出處，還有結合 web search 或是公開確認的資料，讓我能更加系統化學習。」
- 最初提出的方案（尚未成為已確認方案）：模擬考古題系統；教材向量化的語意搜尋知識庫，未來串接 LLM 回答問題。
- 長期期待：「供應給所有需要的備考人」。
- 長期產品方向（使用者 2026-11-16 確認）：「我的大目標是 RAG 系統，結合知識庫跟 LLM 讓我們解題跟搜尋更容易」。這是目標確認，不代表已選定模型、服務、費用或下一輪驗收門檻。
- 最近一次具體情境：準備考試時遇到不會選的題目，用關鍵字逐一搜尋教材 PDF，找到後自行比對各選項。

### 原因假設（未驗證）
- H-01：關鍵字搜尋失敗的主因是題目用詞與教材用詞不同。探索二：BM25 前 5 筆未命中的 5 題中，2 題歸為用詞不同，3 題與標準答案的頁碼判定有關（AI 歸類，26 題的小樣本）。
- H-02：向量檢索比關鍵字搜尋更容易找到題目的依據段落。探索二：26 題中前 5 筆命中，向量 24 題、BM25 21 題；差 3 題，樣本太小，不足以下結論。見[探索二結果](discovery/exploration-2-results.md)。
- H-03：有一部分題目的依據不在教材內，需要外部資料。探索一原結果：50 題中 24 題在科目 1 學習指引內找不到依據（AI 判讀，未複核）；當時未查科目 2，不能據此推論兩科皆無依據。使用者於 2026-11-16 指出兩科相輔相成，並授權下載與互相參照。後續已在科目 2 找到差分隱私、自注意力與量化等概念，現行解析有 21 題列科目 2 的依據或相關頁；僅部分支持原假設，仍有尚未充分查證的內容。探索一標準答案與探索二既有結果保持不變。
- H-04：其他備考人有相同困擾。
- H-05（使用者 2026-11-16 提出）：教材沒有依據的題目，大多數需要的是人對情境的理解，不是再去查某份資料。AI 對 C 類 24 題的粗略看法不完全相同：約 9 題靠題幹情境推理就能答（9、17、19、22、29、36、38、46、47），約 15 題要先知道一個教材沒教的名詞或概念（5、6、7、15、18、24、32、35、37、42、43、44、45、48、50）。這個分法是 AI 單次判讀，未驗證；使用者 50 題全對，本身可能已具備這些名詞知識。

### 第三輪：雙科檢索與 Docker 原型（方向已確認，品質待驗證）
2026-11-16 使用者回覆「可以按照你的規劃進行」，並要求整體以 Docker 控管、維持 CI/CD 與 MLOps 概念。依此採先雙科檢索、再接本機 LLM、最後加自用介面的順序；優先貼題解題。以下原候選內容保留作規劃來源，本輪執行邊界補充如下：
- 本輪為可重現技術原型：雙科索引／檢索 CLI、可替換的本機生成介面、引用檢查、Docker Compose、CI 與評估紀錄。先用少量案例走完整流程，不擴充其他試題或公開服務。
- Docker 分離應用、離線建索引與可選本機 LLM；教材與索引只由 volume 掛載，不放進映像或 CI。CI 跑合成資料測試及容器 smoke test；CD 先準備可手動執行的交付檢查，不自動推映像或部署，避免私有 repo 的額外用量與對外發布。
- MLOps 先追蹤程式版本、原始教材與勘誤雜湊、切塊設定、embedding 模型識別／revision、prompt 版本、檢索結果與延遲；評估與原文只留 data/。不先引入額外模型管理平台。
- 實作前測法：合成測試覆蓋雙科同頁碼識別、勘誤未套用即失敗、索引版本／向量相容性、無命中不生成、未知引用拒絕、本機 LLM 失敗不假裝成功；真實資料另建新基準，不改探索二歷史。
- 工具狀態：本輪起始未找到 Docker CLI；使用者提供捷徑後，已在正常使用者執行環境找到 Docker Desktop 並完成容器實測。容器通過不等於 hosted CI 已通過；生成模型尚未選定或下載。
- 本輪進一步確認：使用者選「先完成檢索，下一步再選 LLM」。本次交付限雙科檢索、Docker、CI／手動交付設定與可追溯評估；生成介面只保留原型草案，不啟動其他專案服務，也不交付網頁介面。
- 已確認目標：讓解題與搜尋更容易，以知識庫結合 LLM 的 RAG 為長期方向；既有不呼叫付費 API、原始資料不進版控及公開限制沿用。
- 現有基礎：雙科教材與頁碼、勘誤處理程式、BM25 與本機 embedding 比較、50 題靜態解析與 14 題人工判定。尚無一般查詢介面或自動生成回答流程，embedding 模型不是生成回答的 LLM。
- 已接受的最小順序：先把雙科教材與適用勘誤整理成可查詢知識庫，回傳教材識別、版本、頁碼與片段；以可核對案例檢查找回的依據，再選本機 LLM 產生帶引用的回答；最後加簡單自用操作介面。生成選型依使用者本輪回覆留到下一步。
- 候選成功判準（暫定，未編正式 AC）：可從問題取得可追溯的教材片段；回答引用實際檢索片段，區分教材支持與推論；證據不足時明說，不能用答案正確掩蓋錯誤引用。先保存逐例結果與延遲基準，再議品質及速度門檻，不自行設定百分比。
- 驗證邊界（暫定）：沿用現有 50 題挑選可核對案例，補入跨科與證據不足情境；現有解析是人工接受的參考，不是全部逐題查證的絕對標準。官方答案及完整解析不混入測試時的檢索語料，避免直接找回答案而誤判 RAG 能力。若另提供已審解析查詢，需標成既有解析來源並分開評估。
- 已確認優先按先前規劃貼題解題，現階段先回傳教材依據；本機 LLM 選型及生成品質門檻尚未決定。本輪未下載或執行生成模型，保留既有不呼叫付費 API 限制。
