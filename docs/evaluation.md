# RAG 完整度與混合搜尋證據

目前定位：能展示教材下載、可追溯索引、混合檢索、PostgreSQL、生成、引用與聊天介面的本機原型。功能串接與工程檢查已有證據；新手獨立安裝、五科混合搜尋品質及多人服務能力仍未驗收。這不是正式產品完成度百分比。

## 保留題評估（2026-11-18）

用官方公告試題與官方答案比較三種檢索下的整題問答。答案自動比對，不需人工標註，可重跑。

**題目**：[examples/ipas/eval/heldout.json](../examples/ipas/eval/heldout.json) 列出 5 份試卷——115 年第二次初級兩科（排除開發期間用過的第 22、20 題）與 115 年第一次中級三科（開發期間未使用）——共 243 題，涵蓋五科教材。開發期間大量使用的 115 年第三次初級科目 1 與 114 年各梯次不納入。設定只記路徑與 SHA-256，試題 PDF 不進版控；部分試卷含圖題未被解析，實際題數以報告為準。

**跑法**：[exam_eval.py](../src/ipas_hub/exam_eval.py) 對每題以 BM25、向量、混合各跑一次；同一個 pgvector 索引、同一模型、iPAS profile、k=5、temperature 0、外搜關閉。每題輪換方法順序；結果逐筆寫入 `data/evaluation/`，可續跑。

**判準**：答對＝模型給出的選項等於官方答案；另計答錯、依據不足、未給選項與錯誤（例如修正後仍引用不存在的片段）。「前五含同科教材」只看檢索結果是否包含該卷對應的教材，**不是**頁碼層級的召回率。答對也不代表理由與引用都正確。三種方法的差異以題為單位做成對 bootstrap（2,000 次、seed 0），報 95% 信賴區間。

**試跑與修正**：開跑前用前 3 題試跑，發現模型會把片段 id 少寫最後的序號（`intermediate1:3-1` 而非 `intermediate1:3-1:0`），導致整題被拒答。改為：只對應到唯一一個教材片段時由程式補全並記錄（`completed_citations`），同頁多段時仍拒答。這項修正與題目內容無關；試跑的 3 題仍包含在正式結果中。

**結果**（243 題 × 3 方法，2026-11-18 完成；索引 `ce5090f4…`、prompt `b9e2e2a7…`、qwen3-vl-8b-fp8、程式為 c82fcb1 加本分支未提交的評估與補全修正）：

| 方法 | 答對 | 答錯 | 依據不足 | 未給選項 | 錯誤 | 答對率 | 前五含同科教材 | 檢索 p50／p95 | 生成 p50／p95 |
|---|---|---|---|---|---|---|---|---|---|
| BM25 | 199 | 5 | 37 | 0 | 2 | 81.9% | 77.0% | 21／30 ms | 6.8／10.4 s |
| 向量 | 204 | 11 | 24 | 2 | 2 | 84.0% | 71.2% | 245／362 ms | 7.1／11.2 s |
| 混合 | 212 | 8 | 22 | 0 | 1 | 87.2% | 74.1% | 242／356 ms | 7.1／10.9 s |

與 BM25 逐題比較：

| 方法 | 改善 | 退步 | 相同 | 答對率差 | 95% 信賴區間 |
|---|---|---|---|---|---|
| 向量 | 16 | 11 | 216 | +2.1 個百分點 | −2.1 ~ +6.2 |
| 混合 | 17 | 4 | 222 | +5.3 個百分點 | +1.7 ~ +9.0 |

各卷答對率（BM25／向量／混合）：初級第二次科目 1 為 87.8／89.8／93.9%，科目 2 為 73.5／81.6／83.7%；中級第一次科目 1 為 87.8／91.8／91.8%，科目 2 為 79.2／75.0／81.2%，科目 3 為 81.2／81.2／85.4%。混合在五卷都不低於 BM25；向量在中級科目 2 低於 BM25。

**怎麼解讀**：

- 在這組題目上，混合比 BM25 多答對 5.3 個百分點，信賴區間不含 0；向量相對 BM25 的差異區間含 0，不能說較好。混合主要是減少拒答（37 → 22），代價是答錯略增（5 → 8）。
- 速度：檢索時間主要花在問題嵌入，混合與向量都約 0.25 秒，BM25 約 0.02 秒；整題時間由生成主導（約 7 秒），所以混合多出的延遲在整題中不到 4%。
- 三種方法都答不對的有 24 題：15 題三者皆拒答、3 題三者皆答錯、6 題混合。拒答原因尚未逐題人工判讀（可能是教材未涵蓋、題目含圖或檢索沒找到）。
- 錯誤共 5 筆，全部是模型修正一次後仍引用不存在的片段 id（例如自創頁碼），程式依規則拒絕輸出，沒有把錯誤引用顯示給使用者。
- 片段 id 補全只發生在 5 筆（4 題）；46 筆經過一次引用修正。補全對整體結果影響很小。
- 「前五含同科教材」與答對沒有強關聯：混合有 55 筆答對時前五不含同科教材（中級題常引用初級內容，或模型本身就知道答案）。因此答對率同時反映檢索與模型既有知識，不是純檢索品質。
- 字詞核對在約六成回答中至少標出一句 ⚠，代表這項提示雜訊高，只能當提醒。

**限制**：單一模型、單次執行（temperature 0 仍可能有少量不確定性）；只比對選項，理由與引用只有下方 20 題的抽樣判讀；題目來自同一年度兩個梯次；排除了開發期間用過的題目，但教材與 prompt 是在其他梯次題目上調整的。逐筆結果、`summary.json` 與報告存在本機 `data/evaluation/heldout-2026-11-18/`，因含試題相關內容不進版控；重跑指令：`uv run python -m ipas_hub.exam_eval --manifest examples/ipas/eval/heldout.json --out <輸出資料夾>`（需本機試題 PDF、pgvector 索引與 vLLM）。

### 答對題的理由與引用抽樣判讀（2026-11-18）

選項答對不代表理由和引用正確，所以從混合答對的 212 題中，每份試卷隨機抽 4 題（seed 0），共 20 題，由作者逐題判讀。評估當時沒有保存回答原文，因此以相同設定重跑取得原文；20 題重跑選項都與正式評估相同。判讀只看被引用的教材片段，不另查資料。逐題判定見 [reasoning-review-2026-11-18.json](../examples/ipas/eval/reasoning-review-2026-11-18.json)（只有題號與判定，不含題目或教材原文）。

| 項目 | 結果 | 95% 信賴區間（Wilson） |
|---|---|---|
| 理由正確（`對`） | 20／20 | 84% ~ 100% |
| 引用完全支持（`支`） | 18／20；2 題部分支持、0 題不支持 | 70% ~ 97% |

兩題「部分支持」的原因不同：

- 一題模型對顯著性圖的說明是正確的，但引用的是 NLP 概論片段，片段裡沒有顯著性圖。理由可能來自模型本身的知識，引用只是掛上相近主題的頁面，字詞核對沒有抓出這一點。
- 一題引用了教材章末練習題的題目文字，而不是概念解釋；練習題本身可以佐證定義，但不是說明。該題題幹也混入了下一題組的情境文字（PDF 解析把題組說明接到前一題），仍答對。

解讀：在抽到的答對題中，沒有發現「理由錯但選項碰巧對」的情況；引用的問題主要是**引用了主題相近但沒有直接支持該句的片段**。樣本只有 20 題，信賴區間寬，判讀者是作者本人而非獨立第三方。

## 後續評估方案（暫定）

保留題評估已完成下列第 1、4、6、7 項的選項層級版本；第 2 項的題型分層、第 3 項的盲審與第 5 項的理由／引用支持判讀尚未執行。

先決定使用場景是自用還是給他人使用，再確認可接受延遲與判準。先量測基準，不事後選一個剛好通過的門檻。

1. 凍結程式 commit、五科 index_id、勘誤狀態、模型 revision、prompt、硬體、k 與 RRF 設定。現行 RRF 各取 BM25／向量前 20，累計 `1/(60+rank)`，預設回傳 5；不是分數直接相加。
2. 從五科與不同梯次選未用於調整的題目，分開列關鍵字明確、同義改寫、跨科、需推理與教材不足。題幹／選項、官方答案、人工依據分開保存；原測試題不放進檢索語料。教材自帶練習題／解答是否保留須預先決定並分層報告，避免洩漏。
3. 先盲審候選片段：隱藏方法、隨機順序，人工判核心支持／部分支持／不支持；保留未判定狀態，另人複核分歧。頁碼相同不代表片段足以支持答案。先選合理數量做標註試跑，再依各科錯誤與比較不確定性擴充，不硬編樣本門檻。
4. 同題比較 BM25、向量、混合，索引／查詢／k 完全一致。先關 web 看內部檢索差異；再用固定或快照外部證據做端到端比較。若即時維基改變，明寫混雜因素。調參集與最後保留測試集分開。
5. 品質至少報：前五有核心支持的題數／分母、首個核心片段排名、選項正確、理由正確、引用支持、合理拒答與錯誤拒答。只有單一目標頁命中率不是完整召回率；未完整標註相關集合時不宣稱 Recall@k。
6. 速度分開量：首次載入、暖機後問題嵌入、資料庫／BM25／融合、外部搜尋、LLM、完整回答。暖機後多輪、輪換方法順序，報 p50／p95、樣本數與硬體；單人與多人並行分開。CI 時間與建索引時間不當線上延遲。
7. 同題成對列出混合改善／退步／持平及失敗原因；報差異與不確定範圍，例如題目為單位的成對 bootstrap。若增益不確定，保留「未證實優勢」，評估多出的向量延遲是否值得。

## 現有工具可以先量什麼

CLI 的 evaluate 接受 `data/evaluation/` 內的 JSON 陣列，每筆有 id、query、expected（source、page 陣列）。它只計算前 k 結果是否命中任何預期頁、每題查詢延遲，不計完整支持、真正召回率、p95 或理由正確性；無依據題要另外人工評估。

先從資料庫取得並固定完整 index_id，在 PowerShell 設定 `$evaluationIndexId` 為實際識別，再執行：

```powershell
foreach ($method in @('bm25', 'vector', 'hybrid')) {
  uv run python -m ipas_hub.cli evaluate --store pg --index $evaluationIndexId --method $method --k 5 --cases data/evaluation/heldout_cases.json
}
```

`heldout_cases.json` 尚待選題與核對後建立；不要拿空白檔或未核對的 AI 頁碼當正式測試集。每次 CLI 另存 data/runs/，保留原始結果；每個命令都重新載入，總 elapsed_ms 含載入，不能直接當暖機查詢速度。上述逐方法一次命令只用於檢查評估管線，不等於完成前述正式比較。

歷史原文與逐例輸出留在 data/；共享報告包含方法、識別、題號、彙總、失敗分析與限制，讓他人能審查結論，也不把受限制教材原文公開。
